SlotMap

Each component type gets its own Slotmap<T, Capacity> instance inside the EntityManager. The SlotMap provides O(1) insert, erase, and lookup while keeping all live data packed contiguously in memory critical for cache performance during forEach iteration.

Template signature

C++// include/darkmoon/ecs/slotmap.hpp
template <
    typename T,
    std::size_t Capacity = 10,
    typename INDEXT = std::uint32_t
>
struct Slotmap;
Parameter Default Description
T - Value type stored (a component struct).
Capacity 10 Maximum number of elements. Fixed at compile-time; set via MAX_ENTITIES in types.hpp.
INDEXT uint32_t Integer type used for indices and generations. Use uint16_t to reduce memory on small worlds.

Internal arrays

Three fixed-size arrays work together to provide stable keys over a packed data buffer. 

textm_indices [ ]  ->  indirection table. Each slot holds:
                    .id  --> position in m_data (when occupied)
                         --> next free slot index (when free, forms the freelist)
                    .gen --> generation counter; incremented on every alloc/free

m_data [ ]     ->  packed array of T. Elements 0..m_size-1 are always valid.
                   Gaps never exist; erase uses swap-and-pop to stay compact.

m_erase [ ]    ->  reverse map: m_erase[dataIdx] = slotIdx that points here.
                   Used to fix up m_indices when swap-and-pop relocates the last element.

Key type

A key_type is a small POD pair returned by push_back. The generation field makes stale-key detection free no extra bookkeeping required at the call site. 

C++using key_type = struct { index_type id; gen_type gen; };

// push_back returns a key
auto key = slotmap.push_back(MyComponent{});

// Access via key  asserts in debug if stale
MyComponent& cmp = slotmap[key];

// Safe validity check before access
if (slotmap.is_valid(key)) {
    slotmap[key].value = 42;
}

// Erase increments generation, invalidates all copies of this key
slotmap.erase(key); // returns false if key was already stale

SlotMap API reference

Method Return Complexity Description
push_back(T&&) key_type O(1) Insert by move. Throws std::runtime_error if full.
push_back(const T&) key_type O(1) Insert by copy (delegates to move overload).
operator[](key) T& O(1) Unchecked access. Asserts validity in debug builds.
erase(key) bool O(1) Remove element. Returns false if key is already invalid.
is_valid(key) bool O(1) Check whether a key still refers to a live element.
clear() void O(N) Reset all slots and reinitialise the freelist.
begin() / end() T* O(1) Raw iterators over the packed data range [0, size).
size() std::size_t O(1) Number of live elements.
capacity() std::size_t O(1) Maximum elements (compile-time constant).

Erase: swap-and-pop

When an element is erased and it is not the last one in m_data, the last element is moved into the freed slot. Three pointer fixups keep everything consistent: 

textBefore erase(key B):           After erase(key B):

m_data:  [ A | B | C ]         m_data:  [ A | C ]
m_erase: [ a | b | c ]         m_erase: [ a | c ]
                                              ↑ C moved here; m_indices[c].id updated

The slot for B is returned to the freelist and its generation is bumped. Any stored key_type for B now fails is_valid() because m_indices[b].gen != key.gen.

The EntityManager stores one Slotmap<CMP, MAX_ENTITIES> per component type in a std::tuple. Access is via std::get<Index>(m_slotmaps), where the index is resolved at compile-time through MP::IndexOf.

Metaprogramming MP::

All compile-time logic lives in the MP:: namespace inside meta_program.hpp. It is a self-contained, zero-dependency header that reimplements the type-traits machinery needed by EntityManager without relying on <type_traits>. Every facility is consteval or resolved at compile-time no runtime cost.

Foundational traits

The header starts by defining its own Boolean and value constants, keeping the namespace self-contained. 

C++// Compile-time constant wrapper
template <typename T, T VAL>
struct constant { static constexpr T value{ VAL }; };

struct true_type  : constant<bool, true>  {};
struct false_type : constant<bool, false> {};

// Type identity helper used as base for "this struct IS type T"
template <typename T>
struct type_id { using type = T; };

// Type equality
template <typename T, typename U> struct is_same : false_type {};
template <typename T>             struct is_same<T, T> : true_type {};
template <typename T, typename U>
constexpr bool is_same_v{ is_same<T, U>::value };

nth_type index into a parameter pack

Extracts the N-th type from a variadic pack via recursive specialisation. Used internally by TypeList and cmp_tag_traits. 

C++// Base case: N == 0 --> the type is the first in the pack
template <typename T, typename... Ts>
struct nth_type<0, T, Ts...> : type_id<T> {};

// Recursive case: strip the head, decrement N
template <std::size_t N, typename T, typename... Ts>
struct nth_type<N, T, Ts...> : type_id<nth_type_t<N - 1, Ts...>> {};

// Convenience alias
template <std::size_t N, typename... Ts>
using nth_type_t = typename nth_type<N, TypeList<Ts...>>::type;

pos find a type's position

Walks the pack at compile-time and returns the zero-based index of T. Triggers a static assert if T is not present. 

C++// Match found at head --> position 0
template <typename T, typename... Ts>
struct pos<T, T, Ts...> : constant<std::size_t, 0> {};

// No match yet --> 1 + position in the rest
template <typename T, typename U, typename... Ts>
struct pos<T, U, Ts...> : constant<std::size_t, 1 + pos_v<T, Ts...>> {};

IFT compile-time if

Selects between two types based on a boolean condition. Equivalent to std::conditional. Used by smallest_type to pick the narrowest integer that fits the bitmask. 

C++template <bool Condition, typename T, typename F> struct IFT          : type_id<F> {};
template <typename T, typename F>                struct IFT<true, T, F> : type_id<T> {};

// Alias for readability
template <bool Condition, typename T, typename F>
using IFT_t = typename IFT<Condition, T, F>::type;

TypeList

The main user-facing type. A variadic struct with no data members pure compile-time information. Exposes three consteval member functions. 

C++template <typename... Ts>
struct TypeList {
    // Number of types in the list
    consteval static std::size_t size() noexcept { return sizeof...(Ts); }

    // True if T appears anywhere in the list
    template <typename T>
    consteval static bool contains() noexcept {
        return (false || ... || is_same_v<T, Ts>);
    }

    // Zero-based index of T; static_assert if not found
    template <typename T>
    consteval static std::size_t pos() noexcept {
        static_assert(contains<T>(), "Type not found");
        return pos_v<T, Ts...>;
    }
};

// Usage
using GameCMPs = MP::TypeList<RenderComponent, PhysicsComponent>;
constexpr std::size_t idx = GameCMPs::pos<PhysicsComponent>(); // --> 1
constexpr bool has = GameCMPs::contains<AIComponent>();         // --> false

smallest_type automatic mask width

Given a TypeList, selects the narrowest unsigned integer that can hold one bit per type. This is the mask_type used by every entity to store its component/tag bitmask. 

C++template <typename LIST>
using smallest_type =
    IFT_t<LIST::size() <=  8, std::uint8_t,
    IFT_t<LIST::size() <= 16, std::uint16_t,
    IFT_t<LIST::size() <= 32, std::uint32_t,
    std::uint64_t>>>;

// Example: 3 components + 2 tags = 5 total --> uint8_t (fits in 8 bits)
// Example: 20 total types                  --> uint32_t
The maximum combined total of components + tags is 64, enforced by a static_assert inside cmp_tag_traits. Exceeding this limit is a compile error.

cmp_tag_traits bitmask engine

The central metaprogramming type consumed by EntityManager. Given the full merged TypeList of all components and tags, it exposes the mask_type and the consteval mask() function used to build query masks at compile-time. 

C++template <typename TLIST>
struct cmp_tag_traits {
    static_assert(TLIST::size() <= 64, "Component tag list is too large");

    // Narrowest uint that fits one bit per type
    using mask_type = smallest_type<TLIST>;

    // Number of types registered
    consteval static uint8_t size() noexcept { return TLIST::size(); }

    // Bit position of a single component or tag
    template <typename CMPTAG>
    consteval static uint8_t id() noexcept {
        static_assert(TLIST::template contains<CMPTAG>(), "Component or Tag not found");
        return TLIST::template pos<CMPTAG>();
    }

    // OR together the bits for all types in the query
    template <typename... Ts>
    consteval static mask_type mask() noexcept {
        return (0 | ... | (1LL << id<Ts>()));
    }
};

// forEach uses it like this (pseudocode):
using Traits = cmp_tag_traits<MergedList>;
constexpr auto queryMask = Traits::mask<PhysicsComponent, TagPlayer>();
// compiled down to a single integer constant zero runtime cost
if ((entity.mask & queryMask) == queryMask) { /* visit */ }
An empty TypeList<> specialisation of cmp_tag_traits is provided so that passing an empty component or tag list to forEach always compiles cleanly and produces a mask of 0 (matches everything).

Type-list transformers

Two additional helpers allow reusing a TypeList with different wrappers, used internally to build the std::tuple of SlotMaps. 

C++// replace_t: reuse the types in a TypeList with a different variadic template
// TypeList<A,B,C> --> std::tuple<A,B,C>
using SlotmapTuple = replace_t<std::tuple, GameCMPs>;

// forall_insert_template_t: wrap every type in a TypeList with another template
// TypeList<A,B,C> --> TypeList<Slotmap<A>, Slotmap<B>, Slotmap<C>>
using SlotmapList = forall_insert_template_t<Slotmap, GameCMPs>;

for_each_in_tuple

A runtime helper that calls a lambda on every element of a std::tuple, iterating by index via template recursion. Used by EntityManager to reset all SlotMaps on destroyAll() and to build bitmask queries that touch each component storage in turn. 

C++// Both const and non-const overloads are provided
// Base case (I == tuple size): do nothing
// Recursive case: call f on element I, then advance

MP::for_each_in_tuple(m_slotmaps, [](auto& slotmap) {
    slotmap.clear(); // resets every component storage in one call
});
